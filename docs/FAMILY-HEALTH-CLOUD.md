# 家安账号云端存储

2026-10-27 发布准备：专用云函数已部署，集合权限已核验 ADMINONLY。真实医疗档案未上传。前端发布结果以维护交接记录为准。

## 数据边界

- 正式页面只读取专用 `family-health` 云函数，复用网站已验证的 CloudBase 登录。账号使用服务端身份 UID，不使用客户端传入的邮箱判断权限。
- `family_health_private` 集合必须设置为 `database.rules.json` 的客户端读写均禁止；仅云函数服务端访问。**在完成权限核验前禁止发布新页面。** 不设置 HTTP 映射。
- 文本快照与附件清单一起提交；图片/PDF 以 192 KiB 分块存入同一私有集合，以账号作用域和内容 SHA-256 定位。附件不放公共静态托管。单文件最大 10 MiB，文本及清单合计最多 700 KB，超限明确拒绝。
- 每次保存保留不可变版本；事务对比版本号，旧设备提交报冲突，不能覆盖新版本。清空及导入不会删除历史快照或附件分块。历史占用需另行制定经确认的保留策略，不自动清理。
- 云端为空显示空档案；不自动读取或上传旧浏览器档案。连接失败显示错误，不用演示数据回退。本地预览使用独立数据，其备份标为 `local-preview`，正式页面拒绝此类导入。
- 导出重新读取云端快照和对应全部附件，校验哈希/大小，带账号 UID、版本、来源和时间。保存中或保存结果不明时阻止导出。已打开但未保存的表单不属于云端记录。

## 发布和迁移（待另行执行）

1. 用户授权部署后，通过现有受保护发布流程发布专用函数；复用既有 `@cloudbase/node-sdk` 版本，不改变全站认证。
2. 创建私有集合并应用拒绝客户端读写规则。验证未登录、匿名、账号 B 无法直接读取或写入账号 A 文档；验证云函数 A/B 隔离、版本冲突及附件往返。
3. `node scripts/build-family-health-auth.mjs` 生成认证桥接包；通过既有发布检查后发布 HTML、桥接包及 `family-health-cloud.js`，后者必须先于 HTML 上线。
4. 保留已恢复的完整 JSON 备份。以正确账号登录，确认界面显示正确邮箱，再由用户明确导入已恢复备份；没有授权时不得代为上传真实健康数据。旧浏览器 IndexedDB 不删除。
5. 核对记录数、药品图片及报告原件，从另一设备登录，导出云端完整备份并对比数据和附件内容。第二真实账号应为空。必须完成这些线上检查后，才能报告云端保存已启用。

## 本地检查

`node tests/family-health-cloud.mjs`：不连接真实云数据库，验证服务端隔离、匿名拒绝、事务冲突、历史快照、重试幂等、图片分块往返、导出新版本、离线及响应丢失。

恢复历史时，根据账号 UID 的 SHA-256 前 32 位定位 `<scope>_v<revision>` 文档，附件仍在同作用域 `b<hash>` 文档中；恢复必须先导出并核对，不能直接覆写 head。线上历史恢复工具尚未提供。
